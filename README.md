# StealthCat server check

Ограниченная по нагрузке диагностика Linux VPS: CPU, память, диск, HTTPS-сеть и состояние Docker-контейнеров до и после проверки. Собственная реализация на Python без сторонних библиотек; код Multitest не копируется.

## Запуск

Нужны Linux, Python **3.10+** и Bash. Для загрузки через оболочку нужен curl. Утилита ничего не устанавливает.

```bash
curl -fsSL https://raw.githubusercontent.com/alkafeu/stealthcat-server-check/v1.0.0/stealthcat-check.sh -o stealthcat-check.sh
bash stealthcat-check.sh --profile quick
```

Загрузчик получает Python-файл из фиксированного тега `v1.0.0`, проверяет SHA256 и выполняет приватную временную копию. Можно сначала просмотреть загруженный shell-файл. При скачивании обоих файлов из репозитория загрузчик также проверяет локальный Python-файл.

Без загрузчика:

```bash
git clone https://github.com/alkafeu/stealthcat-server-check.git
cd stealthcat-server-check
git checkout v1.0.0
python3 stealthcat_check.py --profile quick
```

Root необязателен. Для проверки контейнеров нужен доступ к локальному Docker CLI и сокету. При отсутствии доступа результат состояния контейнеров будет `unavailable`, остальные проверки продолжатся.

## Что проверяется

| Проверка | Ограничение и смысл |
| --- | --- |
| CPU | OpenSSL SHA256, AES-128-GCM и ChaCha20-Poly1305; один поток, по 3 секунды на алгоритм |
| Память | Два буфера по 32 МиБ, до 32 измеряемых копирований; короткий тест с влиянием кеша CPU |
| Диск | Временный файл 64 МиБ, ограниченные прямые запись/чтение; файл удаляется после проверки и при обработанном сигнале |
| Сеть | HTTPS-загрузка Cloudflare/Hetzner, синтетическая отправка Cloudflare, проверка доступности Telegram/GitHub/Docker/OpenAI |
| Контейнеры | Сравнение ID, состояния, времени запуска, счётчика рестартов и OOM; healthcheck учитывается, если настроен |

Для памяти и диска требуется не менее 256 МиБ доступной памяти с учётом cgroup; для диска также не менее 1 ГиБ свободного места. Файловые системы в памяти пропускаются. Если прямой ввод-вывод недоступен, это отмечается в отчёте. Приоритет процесса понижается, а при наличии `ionice` запрашивается idle-класс ввода-вывода.

Профиль `quick` передаёт не более **12 МиБ HTTP body**, либо **16 МиБ** с `--ipv6`. Профиль `default` — не более **32 МиБ**, либо **40 МиБ** с `--ipv6`. Это сумма скачиваемых и отправляемых тестовых тел; DNS, TLS и служебные заголовки в неё не входят. IPv6 включается только явно. У запросов есть таймауты, а загрузка Hetzner требует корректный ответ Range.

Утилита не меняет sysctl, firewall и конфигурацию сервисов, не перезапускает контейнеры, не очищает кеши ядра и не отправляет отчёты наружу. Сетевой тест отправляет только сгенерированное тестовое тело.

## Параметры

```bash
# Профиль по умолчанию, с дополнительной проверкой IPv6
bash stealthcat-check.sh --ipv6

# Без сетевого трафика
bash stealthcat-check.sh --no-network

# Без дискового теста и отправки тестового тела
bash stealthcat-check.sh --profile quick --no-disk --no-upload

# Новый каталог отчёта и существующий каталог для временного файла
bash stealthcat-check.sh --output-dir ./check-result --scratch-dir /var/tmp

# Все параметры
bash stealthcat-check.sh --help
```

Также доступны `--no-cpu`, `--no-ram` и `--no-services`. `--output-dir` должен указывать на новый каталог; существующие результаты не перезаписываются.

## Результаты

По умолчанию создаётся `stealthcat-check-<UTC timestamp>/` с правами `0700`:

- `report.md` — читаемый отчёт;
- `report.json` — структурированные измерения, ошибки и пропуски;
- `measurements.csv` — таблица измерений.

Файлы создаются с правами `0600`. Отчёт может содержать сведения об ОС, сети и контейнерах. Перед публичной отправкой просмотрите его.

Коды завершения:

| Код | Значение |
| --- | --- |
| `0` | Отчёт сформирован; отдельные проверки могли завершиться ошибкой или быть пропущены |
| `1` | Внутренняя ошибка выполнения |
| `2` | Ошибка аргументов или требований к запуску |
| `3` | Обнаружено изменение состояния контейнеров или нездоровое состояние |
| `130` | Прерывание Python-проверки по SIGINT или SIGTERM |
| `143` | Прерывание загрузчика по SIGTERM; сигнал передаётся дочерней проверке |

`unavailable` означает, что состояние контейнеров проверить не удалось. `starting` не считается подтверждённым здоровым состоянием. Контейнер без healthcheck оценивается только по состоянию процесса/OOM: это не проверка работы приложения.

Короткие измерения подходят для первичного сравнения, но не заменяют длительный нагрузочный тест или SLA. Диск зависит от виртуализации и кеширования хоста, память — от кеша CPU. HTTP 401/403 сами по себе не доказывают геоблокировку. Проверки из датацентра не подтверждают доступность VPN с мобильной сети пользователя.

## Разработка

```bash
python3 -m unittest discover -s tests -v
bash -n stealthcat-check.sh
```

Тесты используют подменённые сетевые ответы и команды. Реальные сетевые и нагрузочные замеры в CI не запускаются. Linux требуется для проверок сигналов и загрузчика; на других ОС эти тесты пропускаются. При изменении Python-файла перед выпуском необходимо обновить SHA256 в загрузчике и `SHA256SUMS`, затем выпустить новый тег.
